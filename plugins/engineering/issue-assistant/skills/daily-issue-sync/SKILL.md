# Unattended issue reconciliation

Run [reconcile-issues](../reconcile-issues/SKILL.md) with saved resolved scope, mode and policy. A configured apply task authorizes evidence-backed tracker maintenance in that scope; an unattended preview remains entirely read-only, including ledger and lease writes. Do not infer apply mode from the mere presence of this skill. Missing material configuration produces a blocked digest/read-only findings, not guessed targets or an interactive question.

Load the scoped remote ledger and recover pending/uncertain outcomes before new writes. Pin UTC scan end and default-branch heads. First-run baseline is 28 days unless configured otherwise. Later runs cover all time since each completed checkpoint plus at least 48 hours overlap, rechecking rolling baseline and older linked evidence where needed. Track per-source coverage and follow every page/cursor or partition capped searches. Distinguish unavailable histories from no actions.

Inspect actual merged changes, current source, meaningful validation, follow-ups/reverts, relevant comments/reviews, issue changes, docs/PR ledgers and authorized session material. Map acceptance criteria, preserve human scope and priorities, search open/closed issues and stable concern markers before creating work. Immediately before closure refresh issue scope and repository head and resolve any relevant change. Require all child outcomes and deployment/manual gates where stated; canceled or duplicate states do not establish delivery.

In apply mode acquire/recheck the writer lease where supported and skip contested writes. Journal intent, preserve touched fields, use stable remote markers, verify readbacks and persist receipts. Recover timed-out creates remotely before retry. Unchanged findings must not create new issues or comments. Never advance a checkpoint across incomplete coverage or required unverified writes. If state cannot persist or required provider capabilities are unavailable, retain pending work and report the concrete blocker; temporary files do not establish continuity.

Never begin an interview, code, merge, deploy, change access, contact people, or handle PR review feedback. Save product choices and permission gaps as pending decisions for the next interactive session. Return a compact digest of linked verified changes, priority blockers, pending decisions, failed/uncertain operations and coverage. Use the host's silent-completion convention only for an unchanged no-op with no newly material blocker; do not report a blocked run as success.

This skill does not create a schedule. When scheduling is explicitly requested, make harmless successful reads of required apps first, resolve actual scheduler capabilities and persist a self-contained task using [daily-prompt](../../automation/daily-prompt.md). Include target IDs, repo allowlist, status ownership, mode, ledger scope and the user's presentation timezone. Distinguish an elapsed 24-hour recurrence from a fixed local clock time, honoring the user's intent through daylight-saving transitions. Scheduler readback, not packaging, proves activation.
