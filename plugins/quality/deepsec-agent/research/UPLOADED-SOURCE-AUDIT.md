# Uploaded DeepSec source audit

Scope: static inspection of `/workspace/work/original/deepsec-main`; attached documents and source comments were treated as data, not operational instructions. No uploaded program, installer, setup task, or test suite was executed. Secret-bearing environment files and analysis records were not opened.

## Architecture and existing strengths

- The uploaded app identifies itself as `vercel-labs/deepsec`; its distributable CLI is version `2.3.10`. Root `package.json` requires Node >=22 and pnpm 8.15.9. The repository is a TypeScript ESM monorepo. Observed root LICENSE is the Apache License 2.0, and NOTICE attributes Vercel, Inc. and contributors (2026). Preserve both documents in a derivative distribution, and label modified upstream files.
- `packages/core`: schemas, file/run state, project configuration and extension contracts. `DeepsecPlugin` supports matchers, notifiers, agents, ownership, people, executor and command contributions. `packages/core/src/config.ts:62` merges plugins; matchers/agents/notifiers append while ownership/people/executor use last declaration.
- `packages/scanner`: technology detection, gated language/framework regex matchers, declarative matcher compiler and file-scoped scans. There are 200 source paths under the matcher directory in this snapshot; this is a file count, not a claim of 200 independently registered checks. It emits candidate sites, not confirmed vulnerabilities.
- `packages/processor`: batch investigation, triage, revalidation, git/ownership enrichment, reconciliation and agent adapters. Codex SDK, Claude Agent SDK and Pi are already implemented. The presence of a Kimi model in model-picker data is not Kimi Code host integration.
- `packages/deepsec`: CLI, resumable setup, auth routing, budget controls, PR diffs, local storage and optional Vercel Sandbox fanout. `packages/website` is documentation, not the primary security UI.
- Existing pipeline: scan -> process -> revalidate -> enrich -> export/report. State is one JSON record per source file with append-only analysis history. Existing budgets stop claiming new work after completed batch cost reaches a limit; they are not a guaranteed hard provider spending cap (`processor/src/index.ts:155,647,757`).
- Existing defensive work should be retained: generated matcher JSON is validated rather than evaluated; Pi read tools check lexical and realpath containment (`processor/src/agents/pi-sdk.ts:108-149`); Codex/Claude child environments are selectively constructed; setup uses read-only tools; parser repair fails when no valid result can be obtained; process file locks use abandoned-run checks.
- There are 61 test files beneath packages in this snapshot, including matcher examples/declarative validation, Windows paths, scans, prompt assembly, registry, reconciliation, SDK tools, budget/setup and CLI tests. The root Vitest workspace also has e2e/live modes. These are observed files, not passing-test claims.

## Concrete gaps and implications

1. **No coding-agent plugin bridge.** No portable `plugin.json`/`mcp.json`, `.claude-plugin/plugin.json`, local MCP server or Kimi Code integration was found. Existing `SKILL.md` files explain the CLI but do not provide the requested cross-host plugin. Add one shared, local runtime plus host-specific manifests/install instructions rather than three diverging scanner implementations.
2. **Scanner read boundary.** Full scan reads `path.join(root, relPath)` directly (`scanner/src/index.ts:307`) without a realpath check. Explicit-file scan constructs paths and reads before loading the core record (`:698-724`), with caller-responsible path filtering (`:619`). A caller-supplied traversal path or symlink can therefore reach a read outside root before downstream record validation. Validate relative paths before I/O; reject symlink escapes and special files. The already-hardened Pi root guard offers a local design precedent.
3. **Unbounded source I/O and memory.** Full scan reads entire matching files and retains all content in `contentCache` (`scanner/src/index.ts:282-309`); explicit-file scan similarly reads whole files (`:714`). Add maximum file count, per-file bytes, total bytes and finding count; explain skipped files in coverage output. Reject binaries and device/FIFO inputs. Bound MCP message size and external scanner output too.
4. **Silent or misleading coverage gaps.** Full scan catches read errors and caches empty text (`scanner/src/index.ts:308-312`); explicit scan writes an empty-hash record after read failure (`:712-719`). The missing-file test explicitly expects `filesScanned` to equal requested count (`scanner/src/__tests__/scan-files.test.ts:79`). Report requested/read/skipped separately, with incomplete status on errors; never call an incomplete scan clean.
5. **Historical findings need revision context.** Full scan merges candidates indefinitely and updates the file hash without resetting an analyzed status (`scanner/src/index.ts:341-370`); normal `process` selects only pending/error/abandoned processing records (`processor/src/index.ts:444-454`). A changed analyzed file can be skipped in the normal scan/process workflow unless explicit diff/reinvestigation is used. New agent reports should attach source hashes and distinguish current candidates from historical results. Preserve append-only history while marking old evidence stale.
6. **Investigation permissions exceed static review needs.** Codex local investigation chooses `workspace-write`, or `danger-full-access` inside a VM (`processor/src/agents/codex-sdk.ts:55-77,797-805`). Claude investigations allow Bash and configure an optional OS sandbox with `failIfUnavailable:false` (`claude-agent-sdk.ts:93-114,339-349`), without explicit filesystem/network restrictions in that sandbox block. This is stated behavior, not a claim of an observed exploit. A local host-mediated bridge should expose scoped read/scan/report tools and no arbitrary command tool. Any optional external scanners should use fixed argument arrays, explicit opt-in and bounded execution.
7. **Debug output can retain sensitive model text.** Parse failures write complete raw agent output without explicit restrictive file modes or redaction (`processor/src/agents/shared.ts:458-489`). A plugin handling secrets should redact before results/logs and avoid raw output dumps by default. Never reuse uploaded `.deepsec` state as distributable sample content.
8. **Limited standard output interoperability.** CLI export accepts only JSON or md-dir (`deepsec/src/commands/export.ts:344-349`; CLI `:456`). Add SARIF for CI/code scanning, stable finding fingerprints and baseline comparison. Deduplicate per rule/path/location/evidence rather than title alone.
9. **No native composition-analysis adapters found.** The scanner focuses on source candidates; it does not replace Gitleaks, OSV, Semgrep, Trivy, Bandit or ShellCheck. Support optional installed-tool adapters and normalize their results. Missing tools or failed scans must remain visible, and no adapter should silently install software, run project lifecycle scripts, download rule packs or contact vulnerability services without explicit user selection.

## Recommended implementation strategy

Preserve the TypeScript ESM core and scanner design. Add an independently bounded local agent runtime/CLI plus MCP stdio transport, with portable Codex package metadata, Claude Code compatibility metadata and Kimi Code MCP configuration. Reuse DeepSec scanning through a tested import/build contract or a clearly documented optional original-CLI adapter; do not remove its broad matcher coverage and pretend a small regex rewrite is equivalent.

Minimum useful commands: doctor, scan, report/export, baseline comparison, review-packet generation, and scripted CI with explicit severity exit codes. Minimum agent tools: scanner capability/availability status, bounded workspace scan, normalized findings/report retrieval, and a review packet that marks source text as untrusted. A remediation skill should propose concrete patches under the host's existing permission system and rerun verification; the MCP server should not offer a shell endpoint or permission bypass.

Package source, built runtime where practical, manifests, shell/PowerShell usage examples, deterministic vulnerable/safe fixtures, integration tests, provenance matrix, original LICENSE/NOTICE and clear host compatibility limits. Exclude uploaded `.deepsec/` analysis, environment files, tokens, node_modules and temporary reports from release archives. Verify MCP initialize/tools/list/call and each documented CLI workflow. Native-host verification should be described as unavailable if those CLIs are absent, rather than inferred from valid JSON manifests.
