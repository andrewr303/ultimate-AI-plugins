# Creator-discovery API vendors: live-source research
Read 2026-11-02. Labels: **Confirmed** = read on the primary page or measured live (URL given); **Reported** = secondary source or a search snippet; **Unverified** = not checked or not checkable.
Method note: WebFetch pages are summarised by a small model, so quotes marked "verbatim" come from that summary. Anything I could, I re-checked with raw `curl` (openapi.json, llms.txt, live unauthenticated probes). No API keys were used. Only unauthenticated or public endpoints were called.

## 1. ScrapeCreators (api base https://api.scrapecreators.com, auth header `x-api-key`)

### 1a. Endpoint count: neither 110 nor 175
- **Confirmed**: https://docs.scrapecreators.com/openapi.json (844,916 bytes, downloaded and parsed) has **197 paths / 200 operations** across **33 top-level groups** (about 27 or more platforms plus utilities). 3 paths accept both GET and POST: `/v1/facebook/adLibrary/search/ads`, `/v1/facebook/adLibrary/company/ads`, `/v1/reddit/post/comments`. 4 are `/v1/account/*` housekeeping routes.
- **Confirmed**: "110" is a stale marketing figure. https://docs.scrapecreators.com/integrations/overview and /integrations/agent-skill say "110+ endpoints" / "110+ social media scraping APIs across 27+ platforms". https://docs.scrapecreators.com/llms.txt lists only 120 URLs, and about 14 of those are not endpoints (intros, integrations, guides). The docs index lags the spec.
- **Confirmed**: https://scrapecreators.com and /introduction say "38+ APIs" / "38+ social media platforms". That is a platform count, not an endpoint count.
- **Unverified**: where "175" came from. Nothing on any primary page says 175. It is probably a snapshot between 110 and today's 197. Use **~197 (spec, 2026-11-02)** and re-count from openapi.json at build time.
- Per-platform path counts in the spec: tiktok 29, facebook 23, instagram 20, youtube 18, linkedin 8, twitter 7, reddit 7, spotify 7, cosmos 7, threads 5, pinterest 5, twitch 5, rumble 5, github 10, bluesky 3, telegram 3, snapchat 3, truthsocial 3, kick 2.

### 1b. Credit-balance path
- **Confirmed**: spec path is **`GET /v1/account/credit-balance`**. Response is a single `creditCount` field. Sibling routes: `/v1/account/get-api-usage`, `/get-daily-usage-count`, `/get-most-used-routes`.
- **Confirmed (live probe, no key)**: `/v1/account/credit-balance` -> 401 "Invalid API key" (route exists). `/v1/credit-balance` -> 401 (route exists; this is the docs-page slug https://docs.scrapecreators.com/v1/credit-balance, so it is a working alias). `/v1/credit/balance` -> **404**. `/v1/credits` -> **404**.
- **Verdict**: neither candidate is right. Use `/v1/account/credit-balance`. `/v1/credit-balance` also resolves but is not in the spec.

### 1c. YouTube channel videos and Twitter user tweets
- **Confirmed**: YouTube is **`/v1/youtube/channel-videos`** (hyphen). Params: `channelId` or `handle`, `sort` (latest|popular), `includeExtras`, `continuationToken`. The slash form `/v1/youtube/channel/videos` returns 404 live.
  - Other YouTube channel routes use slashes, so the naming is inconsistent: `/v1/youtube/channel`, `/channel/search`, `/channel/playlists`, `/channel/lives`, `/channel/community-posts`, `/channel/shorts`. Also `/v1/youtube/search`, `/search/typeahead`, `/search/hashtag`, `/video`, `/video/transcript`, `/video/sponsors`, `/video/comments`.
- **Confirmed**: Twitter is **`/v1/twitter/user-tweets`** (hyphen). Params: `handle` (required), `trim`. The slash form `/v1/twitter/user/tweets` returns 404 live. Spec note: "Twitter publicly returns only ~100 of the user's most popular tweets, not chronological or latest."
- Other Twitter routes: `/v1/twitter/profile`, `/tweet`, `/tweet/transcript`, `/search/posts`, `/community`, `/community/tweets`.

### 1d. TikTok audience demographics
- **Confirmed** (spec): `GET /v1/tiktok/user/audience`. Only param: `handle` (string, required). **Costs 26 credits per request.** Returns `audienceLocations[]` with `country`, `countryCode`, `count`, `percentage`. The spec says "Right now you can only get the audience countries", so there is no age or gender.
- Derived arithmetic (not a vendor figure): 26 credits is about $0.049 at the Freelance rate ($1.88/1k) and about $0.026 at the Business rate ($0.99/1k).
- Not in the spec's `cache_max_age` list, so assume no cached discount for this route.

### 1e. Pricing and cache
- **Confirmed** https://scrapecreators.com (homepage; https://scrapecreators.com/pricing returns 404). Tiers as read, 2026-11-02:
  - Free: $0, 100 starter credits. "Claim up to 7,000 more" by telling them how you found them, starring their GitHub repo, and leaving a G2 review.
  - Freelance: $47 for 25,000 credits ($1.88 per 1k requests). Business: $497 for 500,000 credits ($0.99 per 1k). Enterprise: custom, 1M+ credits.
  - "Pay as you go", "no subscriptions", "Credits never expire", "Every plan includes every API". "1 credit === 1 request (for most endpoints). A few use more, and the exact cost is shown in the docs."
- **Confirmed**: cache hits are free. Homepage: "If a result is already in our cache, it costs 0 credits." https://docs.scrapecreators.com/caching: pass `cache_max_age` (days); "Cache hits cost 0 credits"; invalid values return 400; "rolling out to more endpoints over time".
  - Spec check: only **36 of 197 paths** accept `cache_max_age`. They include tiktok/profile, tiktok v2 video, instagram profile, basic-profile and post, youtube channel and video, twitter profile and tweet, threads profile and post, reddit subreddit, find-social-profiles, find-creator-emails, linktree, komi, pillar, linkbio, linkme. Search, list and audience endpoints do NOT take it.
- **Confirmed**: no rate limits, "keep usage below 500 concurrent requests" (https://docs.scrapecreators.com/introduction).
- **Confirmed** per-endpoint costs stated in the spec: find-social-profiles 10; find-creator-emails 1 (no email found) or 10 (any email) or 0 (cache hit, invalid input, failed lookup); tiktok/user/audience 26; transcripts 0/1/10/30 depending on source or AI fallback; instagram post comments up to 15; google company ads up to 25. Many other endpoints do not state their cost in the spec text.
- **Confirmed** (docs changelog, https://docs.scrapecreators.com/introduction): 2026-10-18 and 2026-10-19 Instagram profile error contracts changed. Age-gated -> HTTP 403 `age_restricted:true`, 0 credits. "Profile is restricted"/"unavailable" -> HTTP 404, 0 credits. Legacy 200 placeholders ("private", "Account doesn't exist") still cost 1 credit. `success:true` now means "state determined", so branch on `errorStatus`, not on `success`.

## 2. "SociaVault is the only pay-as-you-go vendor with TikTok audience demographics"

### Verdict: the claim does NOT hold
- **Confirmed**: SociaVault has it. https://docs.sociavault.com/api-reference/tiktok/demographics.md: `GET /v1/scrape/tiktok/demographics`, param `handle`, "26 credits per request", returns `audienceLocations[]` (`country`, `countryCode`, `count`, `percentage`). Country only ("Currently includes audience country distribution").
- **Confirmed**: ScrapeCreators has it too (section 1d): same 26 credits, same `handle` param, same `audienceLocations` shape. The identical cost and schema suggest a shared upstream, but that is an inference.
- **Confirmed**: TikHub (https://api.tikhub.io/openapi.json, 1,058 paths, grepped for demograph/audience) has NO profile-level equivalent for TikTok. It does have `POST /api/v1/tiktok/creator/get_video_audience_stats` (per-video gender/age/region, but it needs the creator's own `cookie`) and `fetch_creator_search_insights` (search-trend insights, not demographics). Douyin has audience-portrait endpoints (China only).
- **Unverified**: LamaTok (pricing page does not mention it; I did not read its full docs), Bright Data (no audience dataset visible on pricing pages), and Apify actors (not checked).
- Practical read: two pay-as-you-go vendors (ScrapeCreators, SociaVault) expose country-only audience data at 26 credits. Cheapest per lookup, derived: SociaVault 26 x $0.00483 = $0.126 (Starter) down to 26 x $0.00199 = $0.052 (Enterprise); ScrapeCreators about $0.026 to $0.049.

## 3. Official and free APIs (what works WITHOUT partner approval)

- **YouTube Data API v3**, https://developers.google.com/youtube/v3/determine_quota_cost ("Last updated 2026-10-15 UTC", read raw):
  - **Confirmed, and a change from the old model**: "default quota allocation of **100 search.list calls**, 100 videos.insert calls, and **10,000 units per day** combined for all other endpoints." Table row: "search list: 100 quota per day. Each call costs 1 quota." So search.list now has its own bucket of **100 calls/day**. The old assumption of "100 units per call out of 10,000" (about 100 searches too, but shared with everything else) no longer describes it. Pagination calls each count.
  - channels.list = 1 unit, videos.list = 1, playlistItems.list = 1, commentThreads.list = 1 (all in the 10,000 pool). Quotas reset at midnight PT. Extensions need a quota/compliance audit request.
  - Practical read: keyword discovery via the official API is capped at roughly 100 result pages a day per project. Enrichment (channels.list, videos.list) is cheap.
- **Reddit Data API**: **Reported** only. The primary pages (support.reddithelp.com, reddit.com/wiki/api, redditinc.com) returned 403 or are blocked in this environment, so nothing here is read from Reddit. Secondary sources (search snippets, e.g. https://www.techloy.com/reddit-api-pricing-in-2026-complete-guide-for-developers-and-businesses/) say: free tier 100 queries/min per OAuth client (10 QPM unauthenticated), averaged over a window; free is for non-commercial use; commercial use needs a separate agreement; "$0.24 per 1,000 calls" is a June-2023 figure that is not confirmed on any current page; Data API Terms revised 2026-07-20 reportedly say fees are at Reddit's discretion. **Unverified** whether self-serve commercial approval exists. Treat Reddit as "needs approval for a commercial product" until read from a primary page.
- **X API**, https://docs.x.com/x-api/getting-started/pricing: **Confirmed** pay-per-usage, "No subscriptions—pay only for what you use". Reads per resource returned: Posts $0.005; Users $0.010; Following/Followers $0.010; Likes/Mutes/Blocks $0.001; owned reads $0.001. Writes: post create $0.015 (with URL $0.200). Counts recent $0.005, all $0.010. Cap: 3 million Post reads per month on pay-per-usage, above that Enterprise. Promotional credits (e.g. $20 on a first eligible card purchase). The old Free/Basic/Pro tiers are not listed on this page. The page does not mention user search or rate limits, so those are **Unverified**.
- **Threads API**, https://developers.facebook.com/docs/threads/keyword-search: **Confirmed** keyword search exists ("public Threads media with specific keywords or by topic tag", TOP or RECENT, filters incl. `author_username`). Needs permission `threads_keyword_search` plus `threads_basic`; until approved, searches only return the caller's own posts ("After approval, public posts will be searchable"). Limit: 2,200 queries per rolling 24h per user across all apps. **No user/account search endpoint documented**. (ScrapeCreators' `/threads/search/users` is scraping, not the official API.)
- **Instagram Graph API**:
  - Business Discovery, https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/business_discovery: **Confirmed** `GET /<IG_USER_ID>?fields=business_discovery.username(<USERNAME>)`; Facebook Login only; caller must be a Business or Creator account; target must be a Business or Creator account (personal accounts not returned); token needs `instagram_basic`, `instagram_manage_insights`, `pages_read_engagement`; returns public fields (followers_count, media_count, media with like/comment counts). Lookup by known username only, no search. App Review requirement and rate limits not stated on this page.
  - **Instagram Creator Marketplace API EXISTS**, https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/creator-marketplace and https://developers.facebook.com/blog/post/2025/09/09/instagrams-creator-marketplace-and-facebook-creator-discovery-apis-are-launching-soon-get-ready/: **Confirmed**. Blog gives launch dates Instagram 2025-10-01, Facebook Creator Discovery API 2025-10-06. Discovery endpoint `creator_marketplace_creators` with filters (creator_countries/states, major_audience_countries/age/gender/device, creator_min/max_followers, creator_interests, creator_language, has_public_contact_email, reels_interaction_rate, follower growth, `query`, `similar_to_creators` up to 5, etc.). Fields include username, biography, country, gender, age_bucket, insights, email, portfolio_url. Permissions: `instagram_creator_marketplace_discovery`, `instagram_basic`, `pages_manage_metadata`, `pages_show_list`, `business_management`. **Standard access (test data only) is automatic; production needs advanced access via app review**, and the brand's Instagram business account must be eligible/onboarded to the Creator Marketplace (else error code 10). Rate limit 5,000 calls per user per hour. The docs do not list eligible countries or user types. So it is available to a brand-side app after review, not a free open API.
- **TikTok**:
  - Research API, https://developers.tiktok.com/products/research-api/: **Confirmed** eligibility is academic institutions in the US, EEA, UK, Canada or Switzerland (and some EU not-for-profits, beta); "independent of commercial interests", not-for-profit or non-commercial research only; approval about 4 weeks. Data: public profiles, follower/following lists, liked/pinned/reposted videos. Not usable for a commercial creator-discovery product.
  - Creator Marketplace / TikTok One API: **Reported** (search snippets of business-api.tiktok.com docs; the registration page fetched empty). Legacy Creator Marketplace endpoints reportedly stopped working 2025-06-30 and were replaced by TikTok One (TTO) endpoints; registration reportedly company-only ("unable to onboard personal accounts or individual developers"). Requires TikTok API for Business registration and authorization from a TTO account. **Unverified** eligibility details; do not assume open access.
- **Bluesky (AT Protocol)**, live test 2026-11-02 from this environment, no auth header: **Confirmed**
  - `GET https://public.api.bsky.app/xrpc/app.bsky.actor.searchActors?q=...` -> 200.
  - `GET https://api.bsky.app/xrpc/app.bsky.feed.searchPosts?q=...` -> 200, but the same call on `public.api.bsky.app` -> **403**, and `api.bsky.app/.../searchActors` -> 200.
  - So actor search is open without auth. Post search worked without auth on the `api.bsky.app` host only. Bluesky has historically required auth for searchPosts and may gate by IP or host, so treat unauthenticated post search as **unstable** and plan for app-password auth. Docs https://docs.bsky.app now 308-redirect to https://endpoints.bsky.app/, which I did not read.
- **Mastodon**, https://docs.joinmastodon.org/methods/search/ plus live tests on mastodon.social: **Confirmed**
  - `GET /api/v2/search?type=accounts` is "Public (without `resolve` or `offset`), or User token + `read:search`"; "full text search is not available to unauthenticated users"; accounts and hashtags are always searchable. Live: 200.
  - `GET /api/v1/directory` is "Public" (params `order` active|new, `local`); live: 200. `GET /api/v1/trends/statuses` live: 200.
  - Per instance: each server sets its own rules and rate limits, and results cover that instance's view only. Directory listing depends on accounts opting in (`discoverable`, seen in the live payload; the docs page did not state it).
