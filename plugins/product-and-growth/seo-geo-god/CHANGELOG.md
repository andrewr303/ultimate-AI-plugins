# Changelog

All notable changes to SEO-GEO-god are recorded here, with absolute dates.

## 1.0.1 - 2026-11-10

- Added `author` (Andrew Rodriguez) to all three manifests.
- Moved the agent index from `agents/README.md` to `references/agent-briefs.md` and listed the six briefs in `.claude-plugin/plugin.json`, so Claude Code no longer parses the index as an agent without frontmatter.
- Added `VALIDATION.md`, which `scripts/validate_plugin.py` requires and which was missing, so the package validation and `test_real_plugin_root_validates` failed.
- Tool version is now 1.0.1 (CLI `--version`, example reports, docs).

## 1.0.0 — 2026-11-03

Initial release. Platform facts and data files are as of 2026-11-01.

### Skills and agents

- 24 skills, each a `skills/<name>/SKILL.md` with `name` and `description` frontmatter only, plus `agents/openai.yaml` display metadata: the router `seo-geo-god`, the audit orchestrator `seo-geo-audit` and 22 focused skills covering technical SEO, rendering, metadata, sitemaps, performance, media, structured data, international, site architecture, migrations, programmatic pages, CI gates, AI-crawler access, agent readiness, citability, entity authority, measurement, content, keyword strategy, local, e-commerce and search data analysis.
- 6 agent briefs in `agents/`: `seo-geo-auditor`, `seo-implementer`, `geo-content-editor`, `ai-access-analyst`, `search-data-analyst` and `seo-geo-reviewer` (four read-only, two writing only assigned files), with handoff fields and consent flags in `agents/README.md`.

### CLI and rules

- Offline-first audit CLI `scripts/seo_geo.py` with the `scripts/seo_geo_lib/` package: Python 3.9+ standard library only, 28 commands, JSON, Markdown, SARIF 2.1.0 and text output, and exit codes 0 (completed), 1 (gate tripped), 2 (usage or input error), 3 (refused by safety policy) and 4 (internal error).
- Live fetching only with `--live`, in four forms (`audit-url`, `access-check`, `robots --url`, `drift snapshot --url`), through an SSRF-guarded, robots-respecting, bounded same-origin client; `--allow-local HOST:PORT` for a local production server.
- Rule catalog `data/rules.json` (rules version 2026.11.0) with 198 rules: 186 emitted in v1 and 12 planned (catalogued, never emitted). `references/rule-catalog.md` is generated from it with `SG rules --format md`.
- Optional, coverage-aware SEO and GEO readiness scores; categories that were not measured stay `null`.

### References, data and templates

- 26 references, including the fact registry `references/current-facts.md` with 93 dated facts (40 F-AI and 53 F-T IDs), each with an evidence label and source, a re-check calendar and a list of unverified claims.
- 7 data files, all `as_of` 2026-11-01: rules, thresholds, an AI crawler registry (41 crawler and agent entries plus the shared AI-training policy token), structured-data feature status, content lexicons, AI referrers and a search-update ledger (69 updates, 5 scheduled items, 20 unverified claims). `SG doctor` reports their age.
- 4 JSON schemas for findings, result envelopes, the crawler registry and the observation ledger.
- 23 template files: JSON-LD examples, three robots.txt policies, `llms.txt`, GitHub Actions and GitLab CI examples, inert opt-in pre-commit and agent-hook examples, an audit report, a content brief, a change record, a measurement plan, a prompt panel, an entity file and a project contract.
- Synthetic example reports for the broken test fixture in `examples/` (JSON, Markdown and SARIF), regenerated byte for byte by the tests.

### Packaging and tests

- Three manifests with the same identity and version: `plugin.json` (Agent Plugins 1.0), `.claude-plugin/plugin.json` and `.codex-plugin/plugin.json`. No hooks, no MCP servers, no telemetry and no update checks.
- `scripts/validate_plugin.py` (offline structure, manifest, skill, link, data and archive checks) and `scripts/package_plugin.py` (deterministic ZIP, re-validated after writing).
- 937 unit tests in 17 `tests/test_*.py` modules (standard-library `unittest`, network blocked), synthetic fixtures under `tests/fixtures/` and 46 routing scenarios in `tests/skill-scenarios.json`.
