# SEO-GEO-god robots.txt template, policy mode: search-and-ai-open
#
# Purpose: allow classic search crawlers, AI search and answer indexers,
# user-triggered AI fetchers and AI training crawlers, and record that
# decision explicitly for each AI token instead of leaving it to "*".
#
# REQUIRES OWNER APPROVAL. Allowing training crawlers lets those vendors use
# the content to train models. That is a business and licensing decision for
# the owner, separate from search visibility. Replace example.com and deploy
# as /robots.txt on every host that serves the site.
#
# Facts as of 2026-11-01 (see references/ai-crawlers.md and
# references/current-facts.md in the SEO-GEO-god plugin).
# Re-check on or after: 2026-12-15, 2027-02-01, 2027-03-01, early 2027
# (Google starts honoring the shared training token) and 2027-09-30.
#
# What this file does not do:
# - robots.txt is a preference, not access control. Protect private paths
#   with authentication.
# - Allowing every crawler does not make a page citable or ranked; access is
#   only the precondition.
# - A CDN or WAF (for example Cloudflare default AI blocking, managed
#   robots.txt or bot rules) can block crawlers before they read this file.
#   Check the live response and the dashboard, not only this file.
# - Named groups do not inherit rules from "User-agent: *". Any Disallow line
#   added for private or low-value paths must be repeated in every group.
#
# Optional statements the owner may add (both are preferences only):
# - Cloudflare Content Signals, inside EVERY group:
#   Content-Signal: search=yes, ai-input=yes, ai-train=yes
# - An explicit pro-training preference through the shared token:
#   User-agent: __usage_ai-training
#   Allow: /
