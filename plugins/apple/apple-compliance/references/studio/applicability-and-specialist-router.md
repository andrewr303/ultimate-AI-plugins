# Applicability and specialist routing

Apply the [operating contract](../operating-contract.md). Use the app’s actual facts, selected lane and current authoritative sources.

## Establish the actual question

Resolve app/publisher, platform, storefronts, distribution channel, selected version/build/submission and requested endpoint. Preparation, upload, processing, beta distribution, review submission, approval and public release are distinct. A generic request to prepare an app does not authorize submission or changing factual declarations. Preserve authorization already given for a concrete action rather than asking the same question again.

Inspect product facts before classifying rules: account access/deletion, digital goods, user content, protected resources, data/SDK flows, extensions and backend availability. Do not infer them from one SDK name, an old checklist or a sample Boolean. Keep unknowns visible and complete independent technical checks while the responsible owner resolves missing product or legal facts.

## Apply the source and evidence boundary

Apple's applicable current rule is the policy authority; third-party tools can implement workflows but cannot grant eligibility or guarantee acceptance. Check platform, storefront, agreement and effective date. A regional commerce or distribution exception is not global. Mac Developer ID notarization, Mac App Store review and iOS alternative distribution are separate lanes.

Classify each finding as satisfied, blocked, unknown or not applicable with a reason. A valid file, signature, archive or static scan proves its checked scope. It does not establish truthful data declarations, content rights, consent, approval or legal compliance. Use the readiness helper only as an evidence-packet aid with its supported profile/stage.

## Completion check

Return the concrete repair or findings, relevant source/applicability, exact local/native evidence, furthest observed remote state and remaining owner facts. If a lane is outside the helper's supported profiles, prepare a manual evidence profile rather than forcing it into a different channel. Keep reviewer credentials and customer records in protected operational fields, not this plugin or public logs.
