# Working contract and handoff templates

Use only the fields that help the task. Prefer the repository's established planning/report location. Avoid creating unnecessary permanent files.

## Brief

```text
Reader / task:
First useful outcome:
Surfaces and files:
Existing framework / version / package manager evidence:
Source facts and unknowns:
Page map / key navigation:
Visual direction:
Checks to execute:
```

## Page plan

| File / route | Reader question | Page type | Source evidence | Navigation entry |
| --- | --- | --- | --- | --- |

For each page, state the reader's success condition and the next useful action. Do not create a page only to fill a template.

## Verification record

| Check | Exact command or manual action | Result | Evidence / limitation |
| --- | --- | --- | --- |

Use **passed**, **failed**, **blocked**, or **not run**. Do not count a missing executable as a pass. Separate source lint, local links, external links, example execution, site build and browser review.

## Handoff

```text
Changed: <concrete edited files and resulting behavior>
Verified: <checks actually executed and meaningful results>
Open: <unresolved facts, unavailable checks, required user choices>
```

Keep the final response proportional to the work. Include a preview or screenshot when it helps the user assess an actual visual change and the host supports it.
