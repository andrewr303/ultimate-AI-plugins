Good documentation gives readers a place to start, a path to follow, and enough evidence to trust what comes next.

Doc Atlas helps coding agents turn repository knowledge into clear READMEs, guides and documentation sites. This self-contained field guide illustrates a visual direction; it does not represent a generated site or a completed browser audit.

Give readers a first success

For a plugin user, the first step is a concrete request. Enable Doc Atlas in a compatible host, open your repository, then ask:

A useful starting promptInspect this repository and improve its README for a first-time user. Keep the existing stack, verify the install command, and give readers a working first example.

For a direct local preflight, unpack the plugin and use Python 3.10 or newer. From the plugin root:

Terminal · read-only inspection
# Replace the path with your repository.
python skills/repo-docs/scripts/repo_inspect.py --root /path/to/repository

# Check a selected Markdown document.
python skills/repo-docs/scripts/docs_check.py --root /path/to/repository --path README.md

The helpers return JSON. Review findings and coverage limits before deciding what to check next.

Design the path, then the page

Start with source evidence and the reader's task. Structure and visual design follow from the question the documentation must answer.

Make verification visible

Each check answers a different question. A clean Markdown preflight cannot establish that an API example works or that a site is accessible.

LayerWhat to establishEvidence
ContentCommands and claims match the repository.Source paths, schemas and meaningful execution
StructureLinks, headings and assets resolve.Local preflight and renderer checks
BuildThe target framework accepts the docs.Actual version-specific project build
ExperienceReaders can navigate and use the result.Mobile, keyboard, themes and search review
Say exactly what was checkedUse passed, failed, blocked or not run. Keep unavailable browser and external link checks visible instead of treating them as successful.

Let clarity carry the design

A restrained visual vocabulary

Use a deliberate heading hierarchy, readable text measure and code blocks that remain useful on a phone. Let one accent identify navigation and action. Preserve the repository's existing brand and theme tokens.

Visuals with an explanation

Choose a diagram when relationships matter, a screenshot when a real interface state helps, and a table when readers need to compare. Keep text equivalents close to the visual.

The right surface for the content

GitHub owns README typography and theme. A docs site can add native navigation, search and components. Check the actual rendering surface before promising a layout or interaction.
